# AI 생기부 보조 생성기 → 나이스 (크롬 확장)

웹앱에서 만든 교과 평어 · 행동특성 및 종합의견 · 창체 특기사항을 나이스 화면에 **번호순으로** 자동 입력하는 크롬 확장입니다. Manifest V3이고, 빌드 과정과 외부 라이브러리가 없습니다.

> 아직 웹스토어 심사 전입니다. 아래처럼 **개발자 모드**로 설치합니다.

## 설치

1. 이 저장소의 `extension/` 폴더를 내려받습니다. (GitHub에서 **Code → Download ZIP** 후 압축을 풀면 `evaluationapp-main/extension` 폴더가 생깁니다.)
2. 크롬 주소창에 `chrome://extensions`를 입력합니다.
3. 오른쪽 위 **개발자 모드**를 켭니다.
4. **압축해제된 확장 프로그램을 로드합니다**를 누르고 `extension` 폴더를 고릅니다.
5. 퍼즐 아이콘에서 "AI 생기부 보조 생성기 → 나이스"를 **고정**해 두면 편합니다.

업데이트할 때는 새 폴더로 바꾼 뒤 `chrome://extensions`에서 이 확장의 새로고침(↻)을 누릅니다.

## 데이터 가져오기

1. 웹앱(https://989-alt.github.io/evaluationapp/)의 결과 · 행발 · 창체 화면에서 **나이스로 보내기**를 누릅니다.
2. 웹앱 탭이 열려 있으면 확장이 바로 가져갑니다. 확장 아이콘의 숫자(배지)가 데이터 개수입니다.
3. 숫자가 안 바뀌면 확장 팝업의 **웹앱에서 다시 가져오기**를 누릅니다.

팝업의 **데이터** 카드에서 교과·행발·창체별 학생 수와 사전 검사(이름 의심 · 허용 외 문자 · 중복 문장)를 확인할 수 있습니다. 이름 의심이나 허용 외 문자가 있으면 웹앱에서 고친 뒤 다시 보내세요.

## 입력하기 (공통)

1. 나이스에 로그인하고 입력할 화면을 연 다음 **조회**를 누릅니다.
2. 그 탭에서 확장 아이콘을 누르면 **화면** 카드에 인식한 화면 이름이 나옵니다. 잘못 인식하면 **화면 지정**에서 직접 고릅니다.
3. **입력** 카드에서 데이터를 고르고 입력 방식을 정합니다. 교과는 **과목**, 자율활동관리는 **데이터**를 직접 골라야 자동 입력 버튼이 켜집니다.
   - **빈 칸만**: 비어 있는 칸에만 넣습니다.
   - **덮어쓰기**: 칸의 글을 데이터 글로 바꿉니다.
   - **이어쓰기 (1학기 내용 뒤에)**: 행동특성 · 자율활동관리 · 동아리활동관리 · 진로활동관리에서만 보입니다. 칸의 1학기 글 뒤에 2학기 글을 붙입니다 (`기존 글(끝 공백 제거) + 이음 + 새 글`). 칸이 비어 있으면 새 글만 넣고, 칸이 이미 새 글로 끝나면(다시 실행) **이미 이어져 있음**으로 건너뜁니다. **이음**은 바로 이어서(공백 없음) · 띄어쓰기 한 칸(기본) · 줄바꿈 한 번 · 줄바꿈 두 번 · 직접 입력(10자까지, Enter = 줄바꿈) 중에서 고릅니다. 고른 방식과 이음은 확장에 기억됩니다. 교과평가(단계 코드)와 학기말종합의견(학기마다 따로 씀)에는 이어쓰기가 없고, 그런 요청이 오면 빈 칸만으로 넣고 알려 줍니다. 글자수(`length`) 열은 어느 방식에서도 쓰지 않습니다(나이스가 계산).
4. **인식 검사**를 누르면 나이스 칸은 바꾸지 않고 어떤 화면(앱)을 쓰는지, 학생·성취기준을 몇 개 찾았는지(교과평가는 성취기준 짝 목록), 교과평가의 단계 코드, 글 화면은 학생마다 **기존 · 새 글 · 합친 바이트**(한글 3바이트)를 보여 줍니다. 교과평가는 단계 항목을 읽으려고 서로 다른 성취기준 두 행을 잠깐 골랐다가 원래 고른 행으로 되돌립니다(칸은 바꾸지 않음).
5. 먼저 **미리보기(저장 안 함)**로 넣어 보고 화면에서 확인합니다. 괜찮으면 **자동 입력 ▶**(입력 후 저장 누르기)를 누릅니다.
6. 결과에 **못 찾은 번호**가 나오면 그 학생은 직접 입력합니다. 화면(DOM) 방식으로 입력했고 표가 길어 스크롤되는 화면이면 아래로 내린 뒤 **빈 칸만**으로 한 번 더 실행합니다. (아래 표의 화면은 나이스 데이터에 바로 넣으므로 스크롤과 상관없이 모든 행에 들어갑니다.)

나이스는 연 화면을 위쪽 탭(MDI)으로 모두 열어 둡니다. 확장은 **지금 보이는 탭의 화면**에만 입력합니다.

- 보이는 화면을 하나로 정하지 못하면(같은 화면 탭이 둘 보이는 등) 입력하지 않습니다. 쓰지 않는 탭을 닫고 **화면 다시 인식**을 누르세요.
- **화면 지정**이나 고른 데이터의 화면이 지금 보이는 나이스 화면과 다르면 입력하지 않습니다(예: 진로활동관리 화면에 동아리 데이터).
- 저장 버튼이 꺼져 있으면 저장을 누르지 않습니다. 입력 중에 키를 누르거나 나이스 화면을 클릭하면 멈추고 저장하지 않습니다.

입력 중에는 나이스 화면에서 **아무 키나 누르거나 중지**를 누르면 멈추며, 멈추면 저장은 누르지 않습니다.

## 화면별 순서

### 교과 (담임)
1. 학생평가 → **교과평가** (교과별 평가): 과목 데이터 선택 → 자동 입력. 성취기준을 행과 짝지어 **단계**(매우잘함 · 잘함 · 보통 · 노력요함)와 **평가결과**를 넣습니다.
   - 짝짓기: ① 성취기준 코드(예: `[6국05-01]`)가 나이스 성취기준 칸(`sccesCtrCn`)이나 코드 칸(`sccesCtrCd`, 끝 공백 무시)에 있으면 코드로, ② 데이터에 성취기준 본문이 있으면 본문으로, ③ 나이스 칸에 코드가 하나도 없으면(실제 나이스는 내부 코드 `12임…`) 학생마다 **순서**로(데이터에 영역이 있으면 영역 `relmNm`도 맞춰서) 짝짓습니다. 순서로 맞춘 경우 "성취기준을 순서로 맞춤"이라고 알리고, 인식 검사의 짝 목록(나이스 행 · 영역 · 성취기준 앞 24자 · 글자 수)으로 확인하게 합니다. 성취기준 수가 다르면 그 학생은 넣지 않습니다.
   - 단계: 나이스는 **행을 골라야** 그 성취기준에 등록된 단계 항목을 불러옵니다. 그래서 행마다 그 행을 골라(`selectRows`, 안 되면 `focusCell`) 항목이 나올 때까지(최대 0.8초) 기다린 뒤 글자(띄어쓰기 무시, "매우잘함 : …"처럼 단계 이름으로 시작하는 항목도)에 맞는 코드를 고릅니다. 고른 행의 콤보로 골라 나이스의 변경 처리가 평가결과를 채우게 하고, 데이터셋에도 코드를 넣습니다. 끝나면 원래 고른 행으로 되돌립니다. 항목이 안 나오는 행은 그 행만 건너뛰고(결과의 "건너뛴 행"), 모든 행이 그렇면 입력하지 않습니다(`level-code-unknown`).
2. **저장**
3. 학생평가 → **학기말종합의견**: 나이스 화면과 팝업에서 같은 과목을 고른 뒤 자동 입력 (교과별 평어가 들어갑니다). 화면에서 고른 과목이 데이터 과목과 다르면 입력하지 않습니다.
4. **저장**

### 행동특성 및 종합의견 (담임)
1. 학생부자료기록 → **행동특성 및 종합의견**: 행발 데이터 → 자동 입력
2. **저장**

### 창의적 체험활동
창체는 영역마다 관리 화면에서 입력합니다. **학생부자료기록**(`els_sdlce06_m00`)은 세 화면의 글이 합쳐지는 화면이라 **확인만** 하고 자동 입력하지 않습니다(입력·인식 검사를 거부합니다).

1. (담임) **자율활동관리**(탭 제목 "자율·자치활동"): 자율 데이터 → 자동 입력 → **저장**
   - 이 칸에는 1학기 글이 **빈 줄로 나뉜 두 구간**으로 들어 있습니다: 자율·자치활동 구간, 그다음 `(부서명(학년-반)) …`으로 시작하는 동아리 구간.
   - **이어쓰기**면 자율 문장은 자율 구간 끝에, (선택) 동아리 문장은 동아리 구간 끝에 붙고, 구간 사이의 빈 줄(`\n\n`, 원래 `\r\n\r\n`이면 그대로)은 유지됩니다. 예: `자율1\n\n(문화예술부(6-5)) 동아리1` → `자율1 자율2\n\n(문화예술부(6-5)) 동아리1 동아리2`.
   - 동아리 문장도 함께 넣으려면 **"동아리 문장도 같은 칸의 동아리 구간에 이어쓰기"**를 켭니다(가장 최근 동아리 데이터). 동아리 데이터만 골라 동아리 구간에만 이어쓸 수도 있습니다(이어쓰기일 때만).
   - 동아리 구간: 괄호 `(`로 시작하는 첫 구간, 없고 구간이 정확히 둘이면 두 번째 구간. 그 앞은 모두 자율 구간입니다. 동아리 구간이 없으면 `기존 글 + 빈 줄 + 동아리 문장`으로 새 구간을 만들고 "동아리 부서명 괄호가 없어 새 구간으로 추가함"이라고 알려 줍니다.
   - 구간마다 이미 새 글로 끝나 있으면 그 구간은 건너뜁니다(다시 실행해도 두 번 붙지 않음). 인식 검사는 구간 수 · 동아리 구간 여부 · 구간별 바이트만 보여 주고 글은 보여 주지 않습니다.
2. (동아리 담당) 동아리담임 → **동아리활동관리** → 학생부자료기록: 부서 선택(날짜 선택 없음) → 동아리 데이터 → 자동 입력 → **저장**.
   동아리 데이터의 **번호는 선생님 담임 반의 출석번호**입니다. 동아리 명단에는 여러 학년·반 학생이 섞여 번호가 겹치므로, 명단에 반이 둘 이상 보이면 입력하지 않습니다. 담임 반 학생만 보이도록 조회한 뒤 실행하세요.
3. (담임) **진로활동관리**: 진로 데이터 → 자동 입력 → **저장**
4. (담임) **학생부자료기록**에서 확인만 합니다(필요하면 나이스의 "동아리특기사항가져오기").

창체 데이터와 화면이 맞지 않으면(예: 진로 데이터를 자율활동관리에) 입력하지 않습니다.

## 실제 나이스 매핑 현황 (0.3.0)

- MDI 선택 탭(`getSelectedTabItem`)은 바깥 탭 앱(예: 동아리 `els_sdlce01_m00`, 교과평가 `els_scres00_m00`)을 돌려줍니다. 보이는 알려진 앱이 없는데 선택 탭이 나이스 업무 화면(`edu/…`)이면 숨은 다른 탭의 제목·표로 짐작하지 않습니다: 선택 탭이 알려진 화면이면 "조회를 누르세요", 아니면 **"아직 지원하지 않는 화면"**(`unsupported-screen`, 앱 id 표시)으로 알리고 입력하지 않습니다. (3차에서 자율활동관리를 동아리활동관리로 잘못 알아본 일의 수정)
- 글자수(`length`)는 나이스가 계산하므로 쓰지 않습니다.
- 교과평가 바깥 탭 앱(`els_scres00_m00`)과 동아리 출결(`els_sdlce01_m05`)의 데이터는 쓰지 않습니다. 저장은 안쪽 앱(`m02`)의 `btnSave`를 누르고, 그 버튼이 화면에 숨어 있으면 바깥 앱(`m00`)의 `btnSave`를 누릅니다.
- **빈 칸만**에서 이미 단계가 들어 있는 행은 단계와 평가결과를 모두 그대로 둡니다(다른 단계에 평가결과가 짝지어지지 않게).
- 위 표의 앱은 데이터셋 방식으로만 씁니다. 데이터 열이 예상과 다르면 다른 cpr 표로 넘어가지 않고 화면(DOM)에 보이는 편집 칸에만 넣습니다.
- 개인정보 열(`stuFlnm`, `stdntNm`, `stuBrdt`, `stdntInfo`, `sameFlnm`, `stuInvlNo`, `userId`, `stuHopMteCn`, `stuHopMteCnOri`, `sxdsScCd`, `clubActDptNm`)은 읽지 않습니다. `stdntInfo`는 학기말종합의견 번호를 찾을 때 **숫자만 있는 값**일 때만 쓰고 원문은 남기지 않습니다.

### 아직 확인하지 못한 것 (다음 구조 수집·실제 입력으로 확인)

1. 교과평가 `sccesCtrCn`에 `[6국05-01]` 같은 코드가 들어 있는지. 3차 표본은 글자 수(31·32·47자)만 있어 확정하지 못했지만, 31자는 코드 없는 본문 길이에 가깝습니다. 코드가 없으면 순서·영역으로 짝짓습니다(인식 검사로 확인). 웹앱이 성취기준의 `area`·`text`를 데이터에 넣어 주면(확장은 이미 받음) 영역·본문으로 더 정확히 짝지을 수 있습니다.
2. 교과평가 단계 항목을 여는 방법: 구조 수집의 `known.levelProbe`가 행 0·1을 골라(`selectRows` → `focusCell`) 읽은 항목, `itemSetConfig`, 콤보 데이터셋을 담습니다. 항목 값이 성취기준마다 다른지, 콤보로 고르면 나이스가 평가결과를 채우는지 이것으로 확인합니다.
3. 콤보(`cmbLvl`)의 `selectItemByValue`가 고른 행에 적용되는지. 다른 행이 바뀌면 그 행을 되돌리고 그 뒤로는 데이터셋에만 넣습니다(결과 안내).
4. 동아리활동관리의 `scrgClsDdlnYn`(마감으로 보임)도 입력 거부 조건에 넣어야 하는지.
5. 자율활동관리 칸의 동아리 구간이 항상 `(부서명(학년-반))`으로 시작하는지, 학생부자료기록의 "동아리특기사항가져오기"가 자율활동관리 칸과 어떻게 합쳐지는지.

## 화면을 못 알아볼 때: 구조 수집

나이스의 실제 화면 구조(컨트롤 이름 등)는 학교·시기마다 조금씩 다를 수 있습니다. 화면을 못 알아보거나 입력이 안 되면:

1. 해당 화면을 조회한 상태에서 팝업의 **화면 구조 수집 (JSON 내려받기)**을 누릅니다. 교과평가 화면이면 단계 항목을 보려고 행을 잠깐 골랐다가 원래 고른 행으로 되돌립니다(읽기만, 칸은 바꾸지 않음).
2. `sgb-neis-scan-<화면>-<날짜>.json` 파일이 내려받아집니다.
3. **구조 수집 JSON을 개발자에게 보내 주세요.** 다음 버전에서 그 화면을 정확히 맞춥니다.

이 파일(300 KB 이하)에 들어가는 것은 다음뿐입니다. 프레임마다:

- 화면 주소의 **경로**(`/…`, 물음표 뒤 값과 `;` 뒤는 뺌), 맨 위 프레임인지 여부, 확장 엔진 버전
- 인식 결과: 화면 이름, 입력 방식(cpr/화면), 행 수, cpr 런타임 유무와 버전, 앱 개수
- 화면 제목에서 찾은 **화면 이름 낱말**(예: "교과평가", "학기말 종합의견") — 제목 원문은 넣지 않습니다
- cpr 앱 id와 (화면 이름 낱말로 줄인) 앱 제목
- 표마다: **머리글 제목**(번호 · 성명 · 성취기준 같은 열 제목), 열 역할, 데이터 열 이름, 행 수, 앞 3행의 칸별 편집 가능 여부, **번호 열의 앞 3개 값**
- (3차) 보이는 알려진 앱(과 바깥 앱·MDI 선택 탭 앱)의 **데이터 컨트롤 목록**: id · 종류 · 열 이름 · 행 수. 40행 이하이고 개인정보로 보이는 열이 없고 코드표처럼 보이는(코드·이름·단계·값 열) 작은 데이터셋만 값(60자까지)을 넣고, 값 중 사람 이름처럼 보이는 것이 하나라도 있으면 값은 하나도 넣지 않습니다
- (3차) 범주 열(영역 · 과목 · 단계 · 성취수준 · 마감 · 체크 등 정한 열만)의 모든 행 값 분포: 서로 다른 값 30개까지(40자) + 개수
- (3차) 교과평가 화면이면 단계 콤보 확인: 쉴 때 항목, `itemSetConfig`, 콤보 데이터셋, 그리고 **행 0과 다른 성취기준 행 하나를 잠깐 골라** 읽은 항목(글자 20자 · 코드 40자). 칸은 바꾸지 않고 원래 고른 행으로 되돌립니다(`restored`)
- (3차) 알려지지 않은 업무 화면(`edu/…`, 보이거나 MDI 선택 탭 안): 표 머리글/본문 열 정보(개인정보 가림), 데이터 열 이름, 행 수, 버튼 id, 입력 컨트롤 id와 연결된 열, 데이터 컨트롤 — 구조 수집 한 번으로 매핑을 더할 수 있게
- 알려진 나이스 화면(위 표)마다: 보이는지 여부, 그리드·머리글·본문·데이터셋·콤보·버튼·MDI의 **메서드/속성 이름**(값 아님), 머리글/본문 열 정보(성명·개인정보 열 이름은 `[개인정보]`로 가림), 단계 콤보 항목(글자·코드), **앞 3행의 개인정보가 아닌 열 값**(번호 · 학년 · 반 · 과목 · 영역 · 성취기준 코드 · 단계 코드 · 활동 영역 · 마감 여부 등), 긴 글 칸은 **글자 수만**, `stdntCn`/`stdntInfo`는 숫자만 있을 때만(아니면 `[비숫자]`), 행 상태
- 컨트롤 목록: id, 종류, 스타일 클래스 이름, 연결된 데이터 열 이름
- 화면 요소 통계: `cl-` 클래스별 개수, `data-ndid` 개수, iframe 개수, 요소 id·클래스 목록
- 첫 표의 머리글 행 HTML (머리글 제목만 남기고 다른 글자는 `…`, 속성 값은 지움)

**학생 이름·생년월일·학생 고유번호 같은 개인정보, 입력 칸 내용, 표 밖의 화면 글자는 들어가지 않습니다.**

## 개인정보

- **성명 열은 읽지 않습니다.** 학생은 번호로만 찾습니다. 웹앱 데이터에도 이름이 없습니다.
- 서버와 통신하지 않습니다. 데이터는 이 브라우저의 확장 저장소(`chrome.storage.local`)에만 있고, 팝업의 **삭제**로 지울 수 있습니다.
- 웹앱의 `localStorage['saenggibu-neis']`만 읽습니다. API 키가 든 앱 저장소(`saenggibu-v2`)는 읽지 않습니다.
- 권한: `storage`(데이터 보관), `scripting` · `activeTab` · `tabs`(나이스 탭에 입력 엔진 넣기), 웹앱 주소와 `*.neis.go.kr`. 다른 `*.go.kr` 주소는 팝업에서 요청할 때만 허용됩니다.

## 개발

```
extension/
  manifest.json
  src/app-bridge.js     웹앱 탭: saenggibu-neis → 서비스 워커
  src/background.js     서비스 워커: 저장 · 배지 · 팝업 ↔ 나이스 탭 중계 (프레임 고르기)
  src/neis-content.js   나이스 탭(모든 프레임): 명령 중계, 엔진 주입
  src/neis-main.js      엔진 (MAIN world): window.__sgbNeis = { detect, scan, fill, inspect, stop }
  popup/                팝업 UI
  icons/                아이콘 (tools/make-icons.mjs로 생성)
  test/mock-neis.html   모의 나이스 화면 6개 (?screen=교과평가 …). ?cpr=1 은 실제 나이스 모양의 cpr 런타임
                        (일곱 화면 앱 + 알려지지 않은 앱(?screen=미지원)이 MDI로 동시에 있고 ?screen= 화면만 보임,
                        ?lvl=row 행마다 단계 항목, ?stdcode=real 내부 성취기준 코드 등), ?cpr=legacy 는 1차 추정 모양
  test/app.html         웹앱 흉내 (bridge 테스트)
  test/run.mjs          Playwright 테스트
```

- 테스트: 저장소 루트에서 `npm run test:ext` (= `xvfb-run -a node extension/test/run.mjs`). Playwright(`/opt/node22/lib/node_modules/playwright`)와 xvfb가 필요합니다. CI에서는 돌리지 않습니다.
- 엔진은 위 표의 화면이 보이면 그 앱의 데이터셋(`getValue`/`setValue`)에 바로 넣고(`strategy: 'cpr-known'`), 다른 cpr 화면은 그리드 API(`'cpr'`), 그 밖에는 화면(DOM)에서 직접 입력합니다(`'dom'`). 결과의 `strategy`가 어느 쪽인지 알려 줍니다.
- 엔진 버전(`neis-main.js`의 `VERSION`)과 `neis-content.js`의 `ENGINE_VERSION`, `manifest.json`의 `version`은 같아야 합니다(테스트가 확인). 다르면 나이스 탭을 새로고침하라고 안내합니다.
- 아이콘 다시 만들기: `node extension/tools/make-icons.mjs`
