# AI 생기부 보조 생성기 → 나이스 (크롬 확장)

웹앱에서 만든 교과 평어 · 행동특성 및 종합의견 · 창체 특기사항을 나이스 화면에 **번호순으로** 자동 입력하는 크롬 확장입니다. Manifest V3이고, 빌드 과정과 외부 라이브러리가 없습니다.

> 아직 웹스토어 심사 전입니다. 아래처럼 **개발자 모드**로 설치합니다.

## 설치

1. 이 저장소의 `extension/` 폴더를 내려받습니다. (GitHub에서 **Code → Download ZIP** 후 압축을 풀면 `evaluationapp-main/extension` 폴더가 생깁니다.)
2. 크롬 주소창에 `chrome://extensions`를 입력합니다.
3. 오른쪽 위 **개발자 모드**를 켭니다.
4. **압축해제된 확장 프로그램을 로드합니다**를 누르고 `extension` 폴더를 고릅니다.
5. 퍼즐 아이콘에서 "AI 생기부 보조 생성기 → 나이스"를 **고정**해 두면 편합니다.

업데이트할 때는 새 폴더로 바꾼 뒤 `chrome://extensions`에서 이 확장의 새로고침(↻)을 누릅니다.

## 데이터 가져오기

1. 웹앱(https://989-alt.github.io/evaluationapp/)의 결과 · 행발 · 창체 화면에서 **나이스로 보내기**를 누릅니다.
2. 웹앱 탭이 열려 있으면 확장이 바로 가져갑니다. 확장 아이콘의 숫자(배지)가 데이터 개수입니다.
3. 숫자가 안 바뀌면 확장 팝업의 **웹앱에서 다시 가져오기**를 누릅니다.

팝업의 **데이터** 카드에서 교과·행발·창체별 학생 수와 사전 검사(이름 의심 · 허용 외 문자 · 중복 문장)를 확인할 수 있습니다. 이름 의심이나 허용 외 문자가 있으면 웹앱에서 고친 뒤 다시 보내세요.

## 입력하기 (공통)

1. 나이스에 로그인하고 입력할 화면을 연 다음 **조회**를 누릅니다.
2. 그 탭에서 확장 아이콘을 누르면 **화면** 카드에 인식한 화면 이름이 나옵니다. 잘못 인식하면 **화면 지정**에서 직접 고릅니다.
3. **입력** 카드에서 데이터를 고르고 **빈 칸만 / 덮어쓰기**를 정합니다. 교과는 **과목**, 창체(학생부자료기록)는 **데이터와 영역**을 직접 골라야 자동 입력 버튼이 켜집니다.
4. **인식 검사**를 누르면 나이스 칸은 바꾸지 않고 어떤 화면(앱)을 쓰는지, 학생·성취기준을 몇 개 찾았는지, 교과평가의 단계 코드를 보여 줍니다.
5. 먼저 **미리보기(저장 안 함)**로 넣어 보고 화면에서 확인합니다. 괜찮으면 **자동 입력 ▶**(입력 후 저장 누르기)를 누릅니다.
6. 결과에 **못 찾은 번호**가 나오면 그 학생은 직접 입력합니다. 화면(DOM) 방식으로 입력했고 표가 길어 스크롤되는 화면이면 아래로 내린 뒤 **빈 칸만**으로 한 번 더 실행합니다. (아래 표의 여섯 화면은 나이스 데이터에 바로 넣으므로 스크롤과 상관없이 모든 행에 들어갑니다.)

나이스는 연 화면을 위쪽 탭(MDI)으로 모두 열어 둡니다. 확장은 **지금 보이는 탭의 화면**에만 입력합니다.

- 보이는 화면을 하나로 정하지 못하면(같은 화면 탭이 둘 보이는 등) 입력하지 않습니다. 쓰지 않는 탭을 닫고 **화면 다시 인식**을 누르세요.
- **화면 지정**이나 고른 데이터의 화면이 지금 보이는 나이스 화면과 다르면 입력하지 않습니다(예: 진로활동관리 화면에 동아리 데이터).
- 저장 버튼이 꺼져 있으면 저장을 누르지 않습니다. 입력 중에 키를 누르거나 나이스 화면을 클릭하면 멈추고 저장하지 않습니다.

입력 중에는 나이스 화면에서 **아무 키나 누르거나 중지**를 누르면 멈추며, 멈추면 저장은 누르지 않습니다.

## 화면별 순서

### 교과 (담임)
1. 학생평가 → **교과평가** (교과별 평가): 과목 데이터 선택 → 자동 입력. 성취기준 코드(예: `[6국05-01]`)로 행을 찾아 **단계**(매우잘함 · 잘함 · 보통 · 노력요함)와 **평가결과**를 넣습니다.
2. **저장**
3. 학생평가 → **학기말종합의견**: 나이스 화면과 팝업에서 같은 과목을 고른 뒤 자동 입력 (교과별 평어가 들어갑니다). 화면에서 고른 과목이 데이터 과목과 다르면 입력하지 않습니다.
4. **저장**

### 행동특성 및 종합의견 (담임)
1. 학생부자료기록 → **행동특성 및 종합의견**: 행발 데이터 → 자동 입력
2. **저장**

### 창의적 체험활동
1. (담임) 학생부자료기록 → 창의적체험활동: 영역 **자율·자치활동** → 자동 입력
2. **저장**
3. (동아리 담당) 동아리담임 → **동아리활동관리** → 학생부자료기록: 부서 선택(날짜 선택 없음) → 동아리 데이터 → 자동 입력.
   동아리 데이터의 **번호는 선생님 담임 반의 출석번호**입니다. 동아리 명단에는 여러 학년·반 학생이 섞여 번호가 겹치므로, 명단에 반이 둘 이상 보이면 입력하지 않습니다. 담임 반 학생만 보이도록 조회한 뒤 실행하세요.
4. **저장**
5. (담임) **학생부자료기록** → **동아리특기사항가져오기**
6. 영역 **진로활동** → 자동 입력
7. **저장**

## 화면을 못 알아볼 때: 구조 수집

나이스의 실제 화면 구조(컨트롤 이름 등)는 학교·시기마다 조금씩 다를 수 있습니다. 화면을 못 알아보거나 입력이 안 되면:

1. 해당 화면을 조회한 상태에서 팝업의 **화면 구조 수집 (JSON 내려받기)**을 누릅니다.
2. `sgb-neis-scan-<화면>-<날짜>.json` 파일이 내려받아집니다.
3. **구조 수집 JSON을 개발자에게 보내 주세요.** 다음 버전에서 그 화면을 정확히 맞춥니다.

이 파일(300 KB 이하)에 들어가는 것은 다음뿐입니다. 프레임마다:

- 화면 주소의 **경로**(`/…`, 물음표 뒤 값과 `;` 뒤는 뺌), 맨 위 프레임인지 여부, 확장 엔진 버전
- 인식 결과: 화면 이름, 입력 방식(cpr/화면), 행 수, cpr 런타임 유무와 버전, 앱 개수
- 화면 제목에서 찾은 **화면 이름 낱말**(예: "교과평가", "학기말 종합의견") — 제목 원문은 넣지 않습니다
- cpr 앱 id와 (화면 이름 낱말로 줄인) 앱 제목
- 표마다: **머리글 제목**(번호 · 성명 · 성취기준 같은 열 제목), 열 역할, 데이터 열 이름, 행 수, 앞 3행의 칸별 편집 가능 여부, **번호 열의 앞 3개 값**
- 알려진 나이스 화면(위 표)마다: 보이는지 여부, 그리드·머리글·본문·데이터셋·콤보·버튼·MDI의 **메서드/속성 이름**(값 아님), 머리글/본문 열 정보(성명·개인정보 열 이름은 `[개인정보]`로 가림), 단계 콤보 항목(글자·코드), **앞 3행의 개인정보가 아닌 열 값**(번호 · 학년 · 반 · 과목 · 영역 · 성취기준 코드 · 단계 코드 · 활동 영역 · 마감 여부 등), 긴 글 칸은 **글자 수만**, `stdntCn`/`stdntInfo`는 숫자만 있을 때만(아니면 `[비숫자]`), 행 상태
- 컨트롤 목록: id, 종류, 스타일 클래스 이름, 연결된 데이터 열 이름
- 화면 요소 통계: `cl-` 클래스별 개수, `data-ndid` 개수, iframe 개수, 요소 id·클래스 목록
- 첫 표의 머리글 행 HTML (머리글 제목만 남기고 다른 글자는 `…`, 속성 값은 지움)

**학생 이름·생년월일·학생 고유번호 같은 개인정보, 입력 칸 내용, 표 밖의 화면 글자는 들어가지 않습니다.**

## 개인정보

- **성명 열은 읽지 않습니다.** 학생은 번호로만 찾습니다. 웹앱 데이터에도 이름이 없습니다.
- 서버와 통신하지 않습니다. 데이터는 이 브라우저의 확장 저장소(`chrome.storage.local`)에만 있고, 팝업의 **삭제**로 지울 수 있습니다.
- 웹앱의 `localStorage['saenggibu-neis']`만 읽습니다. API 키가 든 앱 저장소(`saenggibu-v2`)는 읽지 않습니다.
- 권한: `storage`(데이터 보관), `scripting` · `activeTab` · `tabs`(나이스 탭에 입력 엔진 넣기), 웹앱 주소와 `*.neis.go.kr`. 다른 `*.go.kr` 주소는 팝업에서 요청할 때만 허용됩니다.

- 테스트: 저장소 루트에서 `npm run test:ext` (= `xvfb-run -a node extension/test/run.mjs`). Playwright(`/opt/node22/lib/node_modules/playwright`)와 xvfb가 필요합니다. CI에서는 돌리지 않습니다.
- 엔진은 위 표의 화면이 보이면 그 앱의 데이터셋(`getValue`/`setValue`)에 바로 넣고(`strategy: 'cpr-known'`), 다른 cpr 화면은 그리드 API(`'cpr'`), 그 밖에는 화면(DOM)에서 직접 입력합니다(`'dom'`). 결과의 `strategy`가 어느 쪽인지 알려 줍니다.
- 엔진 버전(`neis-main.js`의 `VERSION`)과 `neis-content.js`의 `ENGINE_VERSION`, `manifest.json`의 `version`은 같아야 합니다(테스트가 확인). 다르면 나이스 탭을 새로고침하라고 안내합니다.
